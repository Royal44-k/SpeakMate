# SpeakMate 3.0 离线路由契约

状态：控制器已采纳的实施规则，尚未实现或通过浏览器验收。范围只涉及现有 PWA 的本地学习入口，不引入新路由框架、依赖或后台。

## 1. 决策与取舍

采用真实的静态 App Router 页面外壳，具体记录在客户端从 IndexedDB 读取。跨外壳的学习导航使用完整文档导航，同一外壳内筛选及标识替换使用经过统一封装的原生 History API。在线、离线走相同规则，不依赖 `navigator.onLine` 判断是否可访问服务器。

这是对默认 Next.js Link 软导航建议的有意例外：本产品要求断网后新建、从未在线访问过的记录也能打开并刷新。仅预取 RSC 或保存曾访问页面不能证明这一点。代价是跨外壳重新加载，需要显式保存来源、滚动位置和进行中状态；不保留跨页动画或仅在内存中的草稿。返回保护与导航状态继续由现有模块统一负责，不另建竞争的全局路由系统。

## 2. 固定入口

|用途|规范路径|客户端参数与规则|
|---|---|---|
|练习创建／恢复|`/session`|明确 `id=new` 才创建；保存后替换为不透明记录 ID；新建可带公开 scene/level/mode/round|
|练习报告|`/session/report`|必须有记录 `id`；缺失不能变成新建练习|
|笔记详情|`/notebook/note`|必须有规范笔记 `id`，从本地读取正文|
|模拟练习|`/notebook/simulation`|恢复用持久化 `id`；新建必须明确 `id=new` 并有合法本地来源|
|场景准备|`/scenes/prepare`|公开 `scene` slug、level、mode；展示场景与记录 ID 分离|

五个一级导航仍是 `/`、`/practice`、`/scenes`、`/notebook`、`/me`。固定入口的页面 HTML 不随查询参数变化，客户端查询读取置于适当 Suspense 边界内；服务器不根据个人记录参数生成页面。缺失、重复、格式错误、未知标识须提供明确恢复入口，不能先默认创建，再异步改为恢复。

历史编号兼容：旧备份已接受的编号范围比新版路由宽，不能通过收紧导入格式、改写旧 ID 或删除记录来解决。已有记录无法表示为新版有界链接时，列表／最近练习使用明确的“在此查看保留记录”操作，在原页提供完整只读原文与导出入口，并解释该编号不能直接链接或从该路由续练；可另行明确创建新练习，原记录不变。一条特殊编号不得使整个页面报错。普通支持的编号维持正常恢复／报告路径，不引入别名注册表、额外存储或通用编号编码器。后续记录簿同样必须将接受的存储标识与可生成链接分别处理，不能对持久化标识直接调用可能抛错的链接构造器。

查询只允许必要的不透明标识和公开选项，不含练习正文、笔记、个人搜索、释义或上下文。冷启动的文档请求可能使同源静态托管方看见这些标识；不承诺“所有 URL 标识绝不上网”。私人搜索和来源正文留在本机。优先复用现有会话／模拟来源字段；确需额外启动上下文时使用有界本地记录与不透明引用，并补全持久化、严格校验、导出恢复和过期／缺失恢复规则。

场景搜索与记录簿搜索的自由输入都属于本地状态，不写入新 URL、RSC 请求或嵌套 `from`／返回链接。公开的类别、等级和时长筛选仍可进入白名单参数。当前 `scene-filter-state` 把 `q` 序列化，`scene-library-route` 会调用 router.replace，卡片继续嵌套完整来源地址；Task3I 接入时须一起改造，不能只删除序列化字段却让以 URL 比较完整筛选状态的逻辑失效。使用有界本地 UI 状态并处理存储拒绝，不为搜索增设数据库服务／通用状态框架。代价是文本搜索不再随可分享的网址传递，应用内返回仍应恢复它。

旧链接或旧记录中的 `q` 可以在客户端明确解读为本地筛选，再从后续规范链接及嵌套来源中移除；不得重新上送它，也不改写不可变历史事件来清理地址。用户从外部打开旧链接时，其首次请求可能已经包含该词，不能宣称能撤回先前请求或提供追溯隐私保证。

## 3. 导航与返回

- 提供统一的类型化 URL 构造、解析、目标识别和跳转接口，供练习、记录簿、目标及底栏使用；禁止各组件自行拼接不同规范。
- 语义页面身份包含路径、记录 ID 和必要子视图：笔记 A → B 是前进，不是同页筛选；筛选变化、新建 ID → 保存 ID 则使用明确的替换规则。
- 新建成功只替换当前历史条目，不复制 Next.js 私有 history 字段；使用框架支持的原生 History API 方式，确保地址和客户端查询同步。不得把 `window.history.state` 的私有框架标记原样作为用户数据传回。
- 跨文档导航仍需经过现有退出确认；取消不丢录音／待确认文字，确认后先保存需要恢复的本地状态、释放临时音频，再导航。不要通过绕过 ExitGuard 获得离线跳转。
- 来源信息只接受已知本地路由；明确区分前进、返回列表、同页筛选和 ID 替换。返回恢复筛选／滚动，不被迟到的标题焦点拉回页首。
- sessionStorage 被拒绝或容量不足不能阻断渲染和返回。安全降级到明确返回入口，不能假称已保存位置。查询变更的异步读取必须取消或忽略旧响应，避免 A 的数据覆盖 B。

## 4. 缓存与旧链接

缓存分为页面外壳、当前构建静态资源、版本化公开语料。外壳只处理同源 GET 文档导航，按**相同规范路径**读取不依赖查询的 HTML；验证成功状态、HTML 类型及最终路径。绝不将首页或练习页 HTML 当作报告、笔记或 RSC 的成功响应。

离线关键跳转不依赖 RSC 软导航。RSC／预取请求不能收到 HTML 回退。只在已验证所有必要页面、脚本、传递依赖、CSS／字体和所选内容后显示相应“可离线使用”；页面外壳就绪与语料包就绪分别说明。缺失时显示可重试的下载／恢复说明，不偷偷换场景、等级或内容版本。

保留旧 `/session/new`、`/session/:id`、`/session/:id/report`、`/scenes/:slug` 的兼容入口：精确识别后，在线和受控离线文档导航均重定向到对应规范入口，只传递白名单参数。排除 report、prepare 等保留路径，禁止宽泛匹配把报告变成新练习。规范化不增加返回绕路，不对 RSC 返回替代 HTML。所有应用内新链接改为规范入口。

缓存升级只清理本应用明确拥有的过期命名空间，考虑旧活动客户端与其固定内容，不删除其他类别缓存、不混用不同构建的页面和脚本，更不清空或降级 IndexedDB。

## 5. 生产资源清单与多窗口更新

允许增加最小的构建生成步骤，使用现有 Node／文件系统工具，从实际生产输出生成有版本、有构建标识的公开离线资源清单。清单只列同源、确实可公开访问的页面外壳、脚本、样式、字体及分类语料资源；不发布服务端文件、源映射、密钥或用户数据。清单生成、校验和生产环境提供方式都要测试；输出结构不支持或必需文件缺失时明确失败，不用空清单宣布离线已就绪。

分类语料仍按需准备，分类与资源的关系必须有实际构建证据，不能仅凭压缩后的文件名猜测。外壳和静态资源按同一构建隔离；不得将全量分类静默塞进初次缓存，再宣称按需下载。若安装版本的构建输出无法给出可靠分类关系，应先提出具体、最小的替代方案，不扩展为通用打包器解析框架。生成完成不等于浏览器已下载，下载完成也不等于缓存永不被系统回收。

手动更新采用保守规则：存在其他同一服务工作线程作用域内的窗口时，暂不触发强制激活，并说明需先完成／关闭其他窗口再重试。不能仅因另一个窗口当前没有录音，就清理它稍后可能需要的旧脚本。未知、未响应的窗口状态同样不视为安全；不自动关闭或强制刷新其他窗口。本窗口仍须通过已有的草稿／录音保护。

在实际实现中说明激活检查与新窗口打开的竞态、旧构建缓存何时可清理，以及旧 2.3 客户端的兼容边界；不能把一次窗口数量检查宣称为跨窗口原子锁。针对实际策略测试延迟资源访问、取消／重试更新和新窗口竞态。只清理本应用确认可废弃的构建缓存，不清空学习数据，不以保留全部历史缓存替代更新策略，也不引入付费版本保护或新的后台服务。

“上一构建”须根据实际激活记录确认，不能以缓存创建顺序或一次成功安装推断。实现可在本应用构建缓存内保存最小、有界且严格校验的激活标记，仅在真实激活过程中写入；删除前确认写入成功。没有窗口时也保留当前与确实的上一激活构建，旧 2.3 兼容缓存另行保留；存在窗口时不删除旧构建。未激活、无有效标记或标记写入失败的缓存不据猜测删除。此保守策略可能积累无法确认的缓存，不能承诺总存储上限或无限期离线可用；容量不足须明确失败并允许重试，不能靠清除学习数据解决。具体实现与新窗口竞态仍需代码测试及后续真实浏览器验证。

实际生产探测没有提供可用于分类的完整动态依赖图，因此采用明确的**公开分类数据边界**，而不以缓存全部 JavaScript 间接下载所有语料。通过现有构建把已校审正文导出为有限、静态的分类 JSON；可使用框架的静态 GET／构建期参数机制，或等价的小型构建导出。实际生成产物与访问方式须验证，不新增运行期学习服务、第三方工具链或手写通用转译器。

新的客户端公开资料适配器沿用内容／解析端口；下载固定同源分类地址，不把练习正文、笔记、选中文字或解析请求写进请求体、查询或路径。解析和对话运算仍在本机。语料和必要的解析资料保持已审查值、版本与来源；客户端不得通过回退或 barrel 导入又携带全量作者模块。剩余共享脚本、样式、字体可以按实际生产静态清单保守准备，分类资料独立按需缓存。

分类载荷做严格有界的场景、等级、版本、数量与结构检查，并与本次清单的确切内容绑定，防止旧资源混用。失败提供重试，不换场景、不把加载失败冒充“未收录”，不宣布分类离线已就绪。已保存会话用自己的有效快照恢复，不要求重新下载；新练习需要对应资料确实可用。报告列出共享资源与分类资料的实际字节数；生产网络验收仍需证明首次准备不会下载其他分类。

生产环境首次打开时，分类下载也必须经过上述验证边界：等待现有服务工作线程实际接管，并用最小的有版本消息／响应证明确认实际分类响应属于其清单校验结果，不能仅凭 `controller` 非空信任旧 2.3。接管、消息或响应发生变更时不使用迟到结果创建记录。接管与证明等待上限 10 秒；分类下载及正文读取另设 30 秒上限，不能把慢网下载挤在接管后的剩余时间里。失败保留选择并提供重试、受支持的 HTTPS 浏览器及完成更新指引；不能把更新入口藏在当前练习页无法到达的位置。不另增第二个清单端点或通用消息框架。开发模式未注册该线程时可保持明确的开发路径，但不能据此宣称生产验证通过。

这会延迟首次资料准备；不支持／禁用服务工作线程或安装失败时，暂不能新建依赖未验证分类的练习，也不能把资料加载失败解释成未收录。已保存的有效快照、历史和备份不经过这个等待门，仍保留本地使用入口。平台的 `ready` 可以无限等待，且有活动注册不等于当前页面一定已被接管，因此应用必须自己处理有界等待与状态验证。[MDN ready](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerContainer/ready)、[MDN controller](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerContainer/controller)。这只是平台依据，不是实际浏览器验收结果。

已有 `SceneImage` 使用八张 `public/scenes/*.webp`（本次核对合计 183,028 字节）。该组件使用固定同源原图地址，关闭其动态图片优化请求，并将这八张现有共享图片纳入清单；不猜测不同屏宽对应的优化器 URL。保留原有占位比例、填充、焦点、替代文字及加载优先级，不改画面或全局图片配置。实际渲染地址、资源校验与生产访问需测试，手机视觉回归另做。

代价：增加一个与安装框架版本相关的构建步骤、公开资料适配器和资源校验；框架输出变化时可能需维护，首次使用未缓存分类仍需下载。八张现有小型 WebP 不再获得动态响应式重编码。即使其他窗口空闲，也可能需要用户关闭它后才能立即更新，以换取较小、保守的更新协议。

## 6. 实施归属与验收

### 历史条目与来源返回的身份补充（实施决策 28）

Task 6 独立审查发现，仅用目标网址在已访问数组中的位置判断后退，会把普通前进和明确的来源返回误判为浏览器后退；来源返回后的原生后退／前进也随之失去正确位置。沿用原 `navigation-history` 管理者和 `speakmate-route-stack` 键，采用有版本、最多 24 条 `{ entryId, route }` 与游标的有界状态；在原生 `history.state` 中使用应用专属字段关联当前条目。浏览器实际历史是事实依据，不以网址相同推断条目相同，不建立第二套路由或持久化数据库。

普通前进、明确来源返回、原生后退／前进和当前条目替换须分别处理。明确来源返回按实际导航动作保留其前后历史，但可恢复来源列表的位置；随后原生后退应仍能回到先前报告。来源意图至多保留一个，严格匹配发起条目和目标、单次消费；未确认、取消、失败或不相关导航不得将旧意图带入以后操作。仅写入意图不证明导航已经成功，须考虑系统离页确认取消的情况。

候选意图只暂存在内存，真实离页后才提交，不用零延时定时器猜测导航是否成功。后续输入、新点击、应用导航调用、历史遍历及页面恢复应清理过时意图；对可观察到的阻止／取消或不确定候选，保守放弃位置恢复而保留安全链接。全部应用来源操作须经过同一管理者。任意外部脚本绕过应用全部入口、在无法观察的系统取消后自动跳到完全相同目标，不宣称能可靠区分；这不是增加通用脚本拦截器或网址协议的理由，真实浏览器中仍须检查应用自身的取消与慢导航。

读取旧字符串数组时保留有用的本地上下文，但不得为旧条目虚构已经对应原生浏览器的标识。标识未知、范围已淘汰、格式异常或存储被拒绝时，以明确的安全本地链接兜底，不声称精确恢复。既有滚动记录二元组兼容、私密搜索不入网址、同页筛选、临时会话 ID 替换及来源日期约定不变。

所有现有读取／重置入口须共同使用该管理者。修改历史状态时保留 Next.js 和其他非本应用字段；退出保护的占位条目不算第二次应用页面访问。须验证占位创建、取消、确认、卸载与 StrictMode 清理，以及 `popstate`／`pageshow`／返回缓存，不让退出保护与导航管理互相覆盖。状态写入失败不影响学习数据，也不能靠清空存储修复导航。增加定向失败后通过的测试；真实浏览器证明仍属于最终验收，不以合成事件冒充。

物理占位也须真正解除，不能只删除状态标记。保存成功后的内部导航或已确认退出，由原退出保护只释放自己仍拥有的占位，并在确认返回对应原条目后再执行原导航；无保护时保持原同步路径。最多一个待完成动作，等待有界，不匹配、超时或失去所有权时不迟到执行旧目标。创建回调须传递等待及失败，不与创建完成后的卸载／StrictMode 清理抢先后退；沿用“已保存但地址未更新”的恢复入口。普通页面调用不能因此绕过未确认的草稿保护，新建临时编号也不得留在可后退到的旧条目中。这是决策 28 的框架协作细化，不新增路由或持久化机制。
