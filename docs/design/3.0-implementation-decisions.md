# SpeakMate 3.0 实施决策与代价

更新：2026-09-10。按实施记录中实际作出判断的顺序整理。本附件说明已批准范围内的工程取舍，不新增产品功能，也不表示全部功能已经实现或验收。规格以根目录 `APP_SPEC.md` 为准；具体接口以对应契约、实现及测试证据为准。

|顺序|采用的判断与理由|代价／判断不适合时的影响|
|---|---|---|
|1|先完成各功能入口，再切换五项底部导航，避免中间版本出现空页面。|导航整合较晚，仍可能需要后续布局调整；未删减任何入口。|
|2|保留旧部署，同时在发布前准备能读取 IndexedDB v2 的兼容回退构建。原 2.3 指定打开 v1，不能直接读取已升级数据库。|增加回退构建与数据验证工作；不能以删库或降级弥补。|
|3|备份身份不同且本机仅有自动生成的空游客时，经预览说明和确认可采用备份身份；两个已有学习历史的不同身份不静默合并。|两台设备各自已有历史时，需要以后另做明确的合并流程；本机数据和备份原件保留。|
|4|语料先做咖啡试点和共享契约，再分七个类别批次编写、阅读与审查，最后整合。|增加交接和跨类别整合成本；2,520 问／5,040 答、五级和 42 场景目标不变。|
|5|记录词句后的撤销，只原子撤销本次保存的变更；后续并发编辑冲突时保留数据并提示。|某些撤销需要用户重新核对，并需一个小型事务接口和凭据；不建设通用版本历史系统。|
|6|网址 slug 与持久化场景 ID 分开：例如 coffee-order 对应 dining-01，旧种子顺序不改变。|映射错误会损坏旧会话和备份关联，必须用固定旧样本验证，不能由新映射同时生成测试预期。|
|7|场景显示版本对应场景快照；分级语料版本在对话包与状态中独立固定，不能要求两者相等。|增加关系校验、往返测试及交接修正；不改写历史版本或增加版本服务。|
|8|版本号、manifest、健康接口和缓存版本在最终审查前修改；发布阶段只部署已审查的确切提交。|开发分支会较早带有未发布的 3.0 标识；命名改变需要重新限定审查，不临时补未审查代码。|
|9|离线详情使用固定客户端页面外壳、必要的不透明标识与公开选项；跨页面外壳采用文档导航，同壳使用受支持的 History API。|跨页会重载，需要显式保留来源、滚动与未保存保护，并验证 HTML／RSC／资源缓存隔离。不透明 ID 仍可能出现在同源冷启动请求中。|
|10|多个类别复用相同的问法元数据映射，提取最小共享助手；正文、路径和审校决定仍逐项编写。|增加共享依赖和既有类别回归；助手不生成正文、不自动标记已审阅，不扩大为对话 DSL。|
|11|场景搜索与记录簿搜索均留在本机，不进入新网址、RSC 或嵌套返回链接。|搜索文字不能随网址分享；需本地筛选恢复和存储失败兜底。旧传入网址已包含的搜索请求无法撤回，后续导航须剥离。|
|12|合法的旧版未分级会话保留原文、只读查看；新版由用户明确创建不同 ID 的新练习。|旧版未结束对话不能原地续接，需要清楚说明；不复制旧引擎或批量转换旧完成证据。|
|13|“可接受的备份历史”和“可以继续执行的对话状态”分别校验，不新增多余持久化标记。|需要一致的恢复分类和不可继续提示；保留合法历史不代表能执行它，不补造缺失话轮。|
|14|正常对话到达终局后先等待用户确认；发布前将完成状态、事件、计划、账本及奖励接入同一个受保护事务。|增加确认状态、恢复路径和跨模块事务测试；不能先标完成再事后补积分。普通退出保留进度，明确停止才是放弃。|
|15|版本 1 的有效练习按所选校审路径达到轮次上限且至少有一次非空回答／改答，或确实达成所选流程，再由用户确认。未覆盖表达和混合帮助不受正确率门槛惩罚，纯帮助、无效流程和提前放弃不算完成。|这是偏宽松的投入判定，本地积分仍可能被刷取或篡改；分别展示提交次数与实际表达次数，任务轮数必须对应它固定的真实路径。|
