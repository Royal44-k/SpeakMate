# SpeakMate 3.0 练习保存与完成契约

状态：2026-09-10 控制器采纳的实施约定，尚未实现或验收。补充 `APP_SPEC.md`；不改变零费用、本地处理和旧数据保留边界。

## 旧记录与恢复

没有 `gradedDialogue` 的旧版会话保持原 ID、状态、时间和对话内容，按历史记录展示。旧反馈明确标注其旧版规则来源；缺少开场白时不从新版语料编造。即使旧场景已不在目录，也应能阅读已保存的文本。

不再用旧引擎原地续写旧版未完成对话。页面解释“旧版练习记录已保留；新版对话需要开始新一轮”，并提供查看旧记录及明确的新练习入口。新一轮用不同 ID，由用户选择当前等级与长度，不复制旧任务完成证据，也不让旧会话覆盖用户的新等级选择。

损坏或不支持的新版状态不能伪装成旧记录、跳转成新练习或触发清库。保留原数据并显示可理解的恢复提示。

本版不增加专门的“整合记录版本”标记。备份格式有效与会话可继续是两个检查：符合现有有界备份规则、但缺少匹配话轮的记录可以保留／导出，必须显示只读恢复状态；不能补造话轮、执行引擎或据此发奖。无效或不支持的内容／引擎版本仍在写入前拒绝。已发现的“状态前进但没有话轮”仅是开发测试样本，不是已证实的线上用户数据。

代价：旧版未完成对话不能原地续接；增加明确的历史／恢复展示与连贯性检查，但不维护第二套对话引擎，也不收紧合法旧备份的导入边界。

## 原子保存边界

复用现有本地存储事务，提供有界的创建、推进、确认完成、停止操作及同一次读取的会话／话轮视图。具体接口名由实现者确定，不暴露通用事务 DSL。

- 创建前加载公开语料；固定会话 ID、时间、模式与变体。创建成功后再替换临时链接；重试不得覆盖或重复创建已保存的会话。
- 推进时在事务内读取最新保存状态，核对调用方预期状态，从该固定快照运行引擎，并一起保存实际文本、回复、话轮序号与新状态。任何一项失败全部回滚。
- 相同提交重试复用原 ID、文本、动作、时间与上下文；返回当前最新记录，不把已有后续话轮倒退。不同内容占用同一提交身份要报冲突。迟到请求不能更新另一个页面或自动把旧草稿答给新问题。
- 普通历史保存接口不得绕过新版记录保护；备份恢复仍是单独校验的操作。内存与 IndexedDB 两种实现都要验证这些关系。
- 存储失败保留草稿，内容错误与状态过期分别解释；不能因设置读取失败或内容无效而静默新建临时会话。

## 对话结束不等于已确认完成

|状态／操作|保存结果与用户可用动作|
|---|---|
|正常对话中|会话 active，引擎 active，可以继续回答|
|达到本轮上限或提前达成交际目标|最后一轮与真实 outcome 一起保存；会话仍 active、等待确认，禁止继续追加回答|
|用户确认完成|重新检查最新证据，一次事务保存 completed、完成事件以及适用的计划、积分和全核心任务奖励|
|用户拒绝／明确停止|保存实际拒绝结果或原状态并标记 abandoned；不伪造达成、不奖励，也不扣分|
|确认前离开或刷新|保留等待确认的终局，恢复后继续确认，不出现新问题、不自动发奖|
|打开或刷新报告|只读展示，绝不执行确认或补发奖励|

完成的是学习流程，不等于所有英语表达都被识别。正常完成的 partial 结果可以显示“本轮练习已完成，部分表达未被本地语料覆盖”，不得说所有交际目标已达成或给出虚构语言评分。

## 本版学习流程判定（规则版本 1）

正常流程以选定且已校审路径的提交上限为准。普通场景仍约为 3／6／10 轮；引擎中的回答、改答和帮助操作均消耗本轮提交次数，界面说明这一点。

满足以下之一，并由用户明确确认，才可完成：

1. 达到正常路径上限，真实 outcome 为 partial 或 achieved，且至少有一次非空的 answer／change 文本提交。帮助与改答可以参与该完整流程，不要求每次都是新答案。
2. 同一固定版本引擎已真实得到 achieved 结果，且存在非空的 answer／change 提交，可以在估算轮数之前确认。

未知、纠正过或没有匹配到参考句的非空文本都计入练习；不判断其“足够好／足够相关”，不以精确匹配率、语法、发音或语义分数设门槛。仅点击帮助耗尽次数、拒绝、提前停止、无效路径或保存失败不满足上述规则。UI 分别记录总提交次数与实际非空表达次数，不将帮助点击描述为开口次数。

任务生成时将所选正常路径的上限写入其目标快照，任务启动校验该路径与 `requiredUserTurns` 一致；不得出现任务要求六轮却启动三轮的情况。已开始任务不因用户另选自由练习长度而修改或继承错误归属。以任务入口的明确说明和另开自由练习入口处理这种选择。日后政策变化须版本化，保留已有证据；本地积分不具备防篡改能力。

代价：混合帮助的完整练习采用较宽松的投入判定，而不是能力判定；避免用户用了帮助便永远无法在固定上限内完成，同时必须清楚区分提交与实际表达统计。

## 任务归属与原子奖励

Task 3I 先实现受保护的读取／推进／确认及上述有界证据，不提前写空结算事件。Task 5 在发布前把实际纯政策接入同一个确认事务：完成会话、原始完成事件、任务状态、单任务积分，以及第三项核心任务完成时的派生事件和额外积分一起成功或失败。

最后一轮先保存、稍后由用户确认是两个有意义的操作；不能变成“已标记完成，稍后再补奖”。现有重复事件会直接返回，不会再次运行结算回调，因此不得依赖重复事件补填原本缺少的奖励。

Task 4 的模拟完成同样向 Task 5 交付真实流程证据与受保护入口，最终发布前在原完成事务接入奖励；历史无任务事件不追溯发奖。复习自评保留自己的复习／打卡含义，不能冒充场景或模拟任务。

完成日期用实际确认时的北京时间；任务归属保留原计划日期。完成证据须有界且独立保留，合法删除来源历史后，既有事件与积分仍可备份恢复。报告、导入和页面加载不重放发奖。

代价：需要扩展现有仓库内部的固定结算操作并增加跨模块事务测试；不新增存储服务、通用事件工作流或“后台补偿”机制。

## 验收重点

- 创建重试、保存成功但 URL 替换失败、跨记录迟到读取；缺少／重复参数不自动创建。
- 两个 IndexedDB 连接从同一状态提交；旧提交重试时已有更新话轮；停止与提交／完成竞态。
- 最后一轮落盘后刷新，只恢复确认；确认事务失败，状态和积分无半写。
- 普通 partial／unknown、混合帮助、仅帮助、提前 achieved、拒绝及模式与任务上限不一致。
- 第三核心任务与额外奖励同事务；重复确认／恢复／查看报告不重复发奖。
- 旧记录不改写；可导入但不可继续的记录清楚提示；合法新版记录导入内存和 IndexedDB 并重开验证。

以上是待实施验收项，不能作为通过证据。
