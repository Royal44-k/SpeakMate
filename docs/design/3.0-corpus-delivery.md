# SpeakMate 3.0 语料分批交付方案

状态：实施顺序细化；没有把现有旧语料计为新语料，也不表示下列内容已经完成。总验收仍以 `APP_SPEC.md` 与主执行计划 Task 3 为准。

## 为什么分批

2,520 个问题与 5,040 个对应回答必须逐项阅读，且共同依赖问题标识、状态推进、历史快照和备份格式。先用一个完整场景验证这些接口，再按类别编写和审查，可以避免先批量写出无法连贯使用的内容。中间批次只在开发分支存在，不以部分语料替代整版发布目标。

## 顺序与门槛

|批次|内容|新增最低问／答|验收重点|
|---|---|---|---|
|3A|共享内容契约、状态引擎、本地解析接口与咖啡点单五级试点|60／120|问题对应答案；三个长度；真实状态推进；旧数据和备份兼容|
|3B|餐饮类别其余五场景|300／600|食品选择与限制一致；退换、议价和服务沟通有实际区别|
|3C|旅行六场景|360／720|证件、日期、行程和替代安排；无实际入境或运输保证|
|3D|日常六场景|360／720|位置、物件、偏好、故障与后续安排，不虚构已完成真实交易|
|3E|职场六场景|360／720|职责、事实、预测、协商和语气分寸|
|3F|社交六场景|360／720|尊重拒绝、邀请边界、修复与不同意见|
|3G|学习六场景|360／720|信息差、澄清、协作、论证和反馈|
|3H|紧急与健康沟通六场景|360／720|只训练表达，不提供诊断、剂量、真实救援或维修承诺|
|3I|全量整合、重复审查、离线内容准备和消费者接口定稿|不靠新增凑数|合计 210 单元、2,520 问、5,040 答及 630 条基础长度路径|

每批只由一个实现者修改代码，提交后由独立审查者检查规格、实现与语言内容，修复完成再进入下一批。批次 3A 通过不代表 Task 3 整体通过。3B–3H 可以按场景文件拆分编写，但不能跳过任一等级或用机械扩展达到数字。

## 内容和证据

- 每个场景等级至少 12 个问题、六类实际交际意图；拓展路径须有约十个真实推进机会，不反复确认已知事实。
- 问题与两条参考回答绑定，保存稳定标识、内容版本、依据和审校记录。不同等级有自己的任务复杂度与语言策略。
- 首次编写为草稿；阅读语法、搭配、问答相关性、分支事实与等级之后，才能记录具体校审结果。自动生成结构不是校审行为。
- 模型辅助阅读与真人教师审校分开计数；本轮不能声称完成未发生的专家认证。
- 源码计数、结构测试、路径测试和语言阅读各有不同证明范围，报告分别列出，不相互替代。
- 本地解析采用已覆盖／部分覆盖／未覆盖的明确结果，不因语料数量较大就声称可以解释任意英语。

## 接口稳定性

3A 的报告应给出可执行的内容加载、创建会话、推进话轮、获取当前答案和查询解析接口，以及保存的快照／状态字段。后续类别只实现该契约；确需改变共享接口时先记录变更原因并补兼容测试。

恢复会话只使用其固定版本快照。当前内容包更新不能在旧对话中途替换问题或答案；导入备份必须保留并验证同一份状态。未知版本应显示可理解的恢复选项，不静默重置或删除历史。

全部类别通过后才允许将新的完整内容体系作为 3.0 发布候选。若任何批次有缺口，记录真实缺口并继续处理，不把现有 42 个场景卡片数量当作语料完成证明。
