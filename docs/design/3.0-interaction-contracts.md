# SpeakMate 3.0 交互契约（实施与审查参考）

状态：已批准规格的细化，不代表页面已实现。延续现有设计系统，不引入新主题。

## 小屏与可访问操作

标题不拆“随时开口”是用户明确要求，优先于一般自动平衡建议；用完整短语单元和适应可用空间的字号实现，不以裁剪、缩放变形或禁用文字缩放实现。200%文字测试要检查真实文字放大，不只改设备分辨率。

底栏五项等宽，不靠横向滚动藏入口；标签始终可见，使用既有 Phosphor 图标。页面内容底部内边距覆盖底栏与安全区，错误提示、输入法和更新提醒不能压住提交键。可见焦点不被浮层遮挡。

200%文字时允许底栏标签折成两行、卡片和栏高增加，并同步增加页面底部留白；不能为了维持固定栏高而裁字、隐藏标签或缩小触摸目标。首页字号需从320px及放大后的完整短语宽度反推，不能只在390px普通字号截图中看起来正确。正常字号和文字放大分别记录测量结果。

词句正文是真实可选文本。长按、系统复制、拖动手柄由浏览器负责；“记录”按钮是完整替代路径，不是二等功能。选词界面能通过点选单词或编辑待存文本完成，不要求用户精细拖拽。不要全局 preventDefault touchstart 或禁用 user-select。

## 状态与返回

|入口|进行中/成功|取消/错误|返回目的地|
|---|---|---|---|
|任务卡|先保存 started，再跳转；完成凭实际学习事件|写入失败留原页可重试|今日计划原日期/卡片|
|练习记录词句|预览→保存→查看或撤销|取消不产生笔记；失败保留选中文字|继续原会话，不跳首页|
|记录簿解析|原文/校审资料/个人备注分区|未覆盖说清范围，不生成虚假解析|原筛选和滚动位置|
|复习|隐藏答案→展示→自评，反馈明确为自评|未自评可退出，不能自动计完成|待复习队列|
|模拟|携带 noteIds/taskKey/来源，刷新可恢复|权限拒绝可用文字；中止可返回|来源笔记或队列|
|报告|保存状态后显示；同一完成事件幂等|失败可重试不重复完成/奖励|对应目标/笔记/练习来源|
|兑换|确认奖励/价格/余额→事务扣除与解锁→查看/使用|余额不足说明获取积分方法；失败不扣分|奖励目录原位置|
|恢复备份|选择→校验→预览→明确确认→事务合并|取消不写；错误说明原因，保留本机原数据|数据管理|

返回参数只能指向应用内已知路由；不得把笔记全文、音频或解释放入 URL。按钮文案是动作和结果，不用笼统“提交”。处理时间较长时有忙碌状态，避免多次点击；失败不清用户输入。

普通前进导航、返回来源和同页筛选要区分处理。沿用现有 `RouteCoordinator`、`SmartBackLink` 与导航历史模块，不再并行增加另一套全局滚动监听。框架 `scroll={false}` 只表示不主动寻找页首，并不自动保存每个列表的筛选、记录标识和滚动位置；返回记录簿、任务卡、场景列表仍须验证真实恢复。新页面标题可接收焦点；返回列表不能被迟到的标题聚焦再次拉到顶部。会话临时链接替换为真实 ID 时，不额外制造一层返回历史。

保存预览若采用对话框，应有可见标题、关闭／取消、合理初始焦点及关闭后回到触发控件；失败保留输入并把提示放在字段附近。成功反馈不抢占输入焦点，撤销操作不能被底部导航或键盘挡住。按实际固定栏高度设置滚动留白，放大文字后同样有效。页面级存储不可用时，导航仍应能够使用明确的返回入口，不因保存滚动／导航历史失败而中断渲染。

历史删除由现有会话仓库的一次事务执行，不由界面分别删除话轮和会话。确认前列明所选练习及影响；活跃记录另提示删除后不能继续原记录。根据当前显示的完整记录核对新鲜状态，另一窗口已更新时应重新读取、确认，不删除迟到的新进度。成功后本页提供有界、实例内撤销凭据（最多 32 份），明确刷新／离开后不保证撤销。撤销只恢复本次删除的原会话及话轮，不覆盖同 ID 新数据；个人身份变更、相关记录被复用或原子校验失败时保留现状并提示。失败的删除／撤销不出现半写入或成功提示，成功撤销不重发奖励。

已保存笔记和收藏及其上下文副本、计划、学习事件、积分与奖励不随来源历史删除。删除不是完成或停止动作，不产生学习事件或奖励；原任务保持固定目标与进度。若未完成任务的原记录已删除，返回目标页应如实说明，并以原计划日期、目标、来源和资料版本明确另开一条练习，而非声称继续已删除记录。已完成任务不因删除而重新领奖。导出及恢复仍须保留这些合法关联；不新增删除标记数据库或通用历史版本系统。

删除确认还须说明保留范围：现有任务完成凭据可能包含造句等学习文字，笔记也有上下文副本，因此只删除会话与话轮不能称为“所有练习文字已彻底删除”。需要完全清除本机学习内容时，指向已有数据管理的明确清空确认；不隐瞒保留数据，也不为修改文案而改写不可变学习事件。

记录簿搜索词可能包含私人练习内容，应在本机保存筛选状态，不把搜索正文编码进会提交给服务器的查询参数。页面路由只携带必要的不透明记录标识，任务/笔记上下文从本机存储读取。

离线验收必须包含“断网后新建的笔记和模拟练习”，不能只回看在线时访问过的详情。详情入口宜使用已缓存的静态客户端页面及本地标识；若采用动态路由，必须证明从未在线请求过的新标识也能正确打开。Next.js 的页面 HTML、RSC 响应与不同路由不能混用缓存，否则可能复现返回后页面错位或展示错误记录的问题。

后续路线已具体采纳 [离线路由契约](3.0-offline-routing.md)：使用固定外壳和客户端标识，而不是继续依赖任意动态详情路径。跨壳文档导航是明确的离线取舍，须适配既有返回保护；同一路径的不同记录要按语义身份区分。上段动态路由是早期验收边界，不再是可随意选择的实现路线。

## 视觉/信任说明

奖励是成人化的本地学习纪念，不出现现金价值、倒计时逼迫、连续中断惩罚或假社交反馈。演示榜标题附近持续展示“示例数据，非真实好友排名”，真实个人成绩另一区域。部分/未覆盖解析使用文字说明，不能只靠颜色。
