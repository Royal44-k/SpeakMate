# 历史概念：微信小程序路线

**资料性质：根据本任务中用户提供的早期规划整理的概念档案，不是发现的原始文件，不是当前实施规格。** 原对话未提供可核对的创建日期，因此不补造日期。当前开发请阅读根目录 [APP_SPEC.md](../../APP_SPEC.md)。

## 当时的产品设想

最初设想 SpeakMate / 口语搭子为微信登录的成人英语场景陪练：选择场景、扮演角色、轮次式语音对话、单轮纠错、场景报告、持续练习。初期面向 A2–B2，拟约 12 个旅行/职场/生活/社交场景，后来用户要求免费使用、扩大场景及等级覆盖。

初始商业规划曾为每日免费额度与会员订阅，支付待资格具备后开启。后来用户明确本地、零新增费用，本版不启用商业化与后台。实时全双工、音素级评分、真人教师、社区与原生客户端不在最初 MVP 内。

## 当时的技术候选

小程序：Taro、React、TypeScript；后台：React/Vite；服务端：NestJS 模块化单体与 OpenAPI；数据：PostgreSQL/Redis/COS；部署：腾讯云 CloudBase Run；ASR/LLM/TTS 拟采用腾讯云适配器。微信临时 code 交换应用登录态、服务端密钥管理、上传签名、幂等扣配额等属于当时计划，不是本仓库现有能力。

安全设想包括私有音频、限期删除、明确麦克风授权、账号注销/导出、内容安全与日志脱敏。原计划估计 6–8 周开发内测，不含外部审核，这只是当时估计，不作为实际工期承诺。

## 转向 PWA 后的变化

用户随后确认改走 PWA、免费使用、中国大陆与移动端视觉方向。实际可追溯代码从 PWA 2.0 规格开始；3.0 明确不要求微信账号，不配置腾讯云链路，不依赖电脑 MySQL，浏览器 IndexedDB 为本地学习存储。

保留此档案是为了说明决策来源，不应据此创建云账户、开启订阅、开发小程序或添加真实好友服务。这些都需未来单独产品设计与授权。
