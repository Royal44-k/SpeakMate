## 2. 排除与原件保存

- 永久排除 `.env.local`、CLI auth/token、`.vercel` 本机关联、浏览器 profile、真实学习 JSON/音频。
- 不打包依赖安装目录、Node/浏览器运行时、`.next*`、旧生成离线清单、缓存及整个 `.superpowers` 任务运行目录。
- 原历史只纳入三个本来已跟踪的工程报告/核验脚本；它们不是授权配置。绝不因这三个文件存在而复制同目录下 auth、运行时或任务内部状态。
- 未跟踪 QA 共 697 个文件；其中 140 份小型白名单文本/图像作为隔离合成测试补充。其余 **557 个、346,177,473 字节**保留原机，详见 `excluded-test-output.json`；主要是 trace ZIP、`.last-run.json`、大型合成备份及非白名单产物。
- 依赖可由锁文件重新安装；旧源码可由 Git 历史恢复。未纳入的原机文件没有删除。

公开资料不含用户练习记录备份；`outputs/qa` 中明确标识的 synthetic JSON 是测试生成的演示数据，不可导入自己的正式学习库当成绩。文档中指向排除附件的历史链接不伪造替代文件，查看排除清单和对应记录说明。

## 4. 完整性与限制

最终 `file-manifest.json` 列出每个可分发文件的相对路径、字节、SHA256；排除清单本身，避免循环哈希。`.gitattributes` 将文本按 LF 保存以适配跨系统克隆及 GitHub ZIP；原开发目录不改。原文快照与 QA 的内容保留，行尾规范化不作为语言或测试修改。根级交付校验文件记录 ZIP 与 Git bundle 的 SHA256。

在解压的源码根目录执行 `node docs/archive/verify-package.mjs` 可以逐项复核；验证器只读文件，不联网、不处理你的学习库。维护者增加文件时先审查并暂存，再用 `--write` 生成新清单。不要用重写清单来掩盖来源不明的改动。

`source-history-audit.json` 覆盖基线全部可达历史 blob 及跟踪工作文件的密钥格式/禁入路径规则。本次最终副本也再次校验。自动模式扫描不构成“绝无秘密/版权/截图隐私问题”的保证，新增公开内容仍需审查；不上传缺少来源的个人记录。

源码 ZIP 用于直接解压阅读与运行；Git bundle 用于恢复历史，不能双击运行 App，也不应将 bundle 再提交到源码库形成重复。上传后以远端 commit/tree 对比确认，不能以本地打包成功声称已上传。
