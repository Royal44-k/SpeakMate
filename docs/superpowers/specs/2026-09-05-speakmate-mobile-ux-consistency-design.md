# SpeakMate 移动端 UI/UX 一致性升级设计规格

- 文档版本：1.0
- 日期：2026-09-05
- 状态：设计方案已批准，待书面规格复核
- 适用版本：SpeakMate PWA 2.1.1 之后的下一版本
- 目标终端：iPhone Safari/PWA、Android Chromium/PWA、手机微信内置浏览器的网页访问
- 视觉基线：沿用 `design-system/speakmate/MASTER.md` 中的 Dialogue Stage 设计体系
- 设计决策：采用“移动导航壳 + 有状态任务流”方案

## 1. 背景与问题

SpeakMate 已具备从新用户引导、场景选择、语音或文字练习、单轮反馈到场景复盘的完整闭环，也已建立 Atlantic、Sky、Coral 和 Barlow Condensed 为核心的视觉语言。本次升级不更换品牌方向，不重做内容体系，目标是把现有 PWA 收敛为行为可预测、符合手机 App 心智且适合 iPhone 主屏幕运行的统一体验。

2026-09-05 在 390 × 844 手机视口完成了当前版本的全流程取证。审查证据保存在 `artifacts/ux-audit-2026-09-05/`。主要问题如下：

1. Service Worker 更新提示固定在页面顶部，会遮挡首屏、引导标题和练习首页标题。
2. 场景库固定以 A2 打开，与已保存的 B1 用户等级不一致。
3. 场景筛选只保存在组件内存中，进入详情再返回后可能丢失；横向筛选虽可滑动，但没有可发现性提示，当前选项也可能滑出可视区。
4. 场景准备页和安装页缺少统一、可见的返回入口；不同次级页面采用了不同的导航结构。
5. 对话页打开文字输入后，固定语音操作区会遮挡输入、取消和提交区域；展开反馈也容易被底部操作区挡住。
6. 部分筛选按钮和返回入口小于产品设计系统规定的 44 × 44 px 触控区域。
7. 安装页依赖平台识别决定是否渲染说明；无法识别时只有概念性首屏，没有 iPhone/Android 的可执行步骤。
8. 路由切换后的焦点、页面标题播报、纵向滚动复位、横向滚动恢复尚未形成统一契约。

## 2. 目标与非目标

### 2.1 目标

1. 建立适用于全部现有页面的移动导航层级、返回行为和安全兜底规则。
2. 让浏览器返回、iPhone 左边缘返回手势和站内返回按钮得到一致结果。
3. 保证固定导航、语音操作区、更新提示和虚拟键盘不会遮挡主要内容或当前焦点。
4. 让场景筛选、用户等级、路由 URL 和返回后的页面状态保持一致。
5. 为纵向长列表与横向筛选提供明确、可恢复、可访问的交互。
6. 使所有现有核心页面符合产品既有的 44 px 触控、安全区、响应式和减少动画规则。
7. 把尼尔森十大可用性原则转化为可测试的产品行为。
8. 建立覆盖 Chromium 和 WebKit 的自动化验收矩阵，交付时报告“未发现已知缺陷”，而不是作无法证明的绝对零缺陷承诺。

### 2.2 非目标

1. 不更换现有色彩、字体、插画、图标库和 Dialogue Stage 视觉方向。
2. 不增加订阅付费、社交、排行榜、真人教师或新的 AI 能力。
3. 不改造场景内容模型、ASR/LLM/TTS 提供商或数据同步架构。
4. 不新增手势驱动的自定义页面转场；优先使用平台原生滚动与历史行为。
5. 不引入通用 UI 组件库替代当前 CSS Modules 和设计令牌。
6. 不实现完整虚拟化列表；42 个场景尚未达到需要虚拟化的规模。

## 3. 设计原则与验收含义

本次升级使用尼尔森十大可用性原则作为审查框架，并为每项原则规定可执行行为。

| 原则 | SpeakMate 设计要求 |
| --- | --- |
| 系统状态可见 | 加载、录音、处理中、离线、更新、保存和完成状态必须出现在用户当前操作附近，且不遮挡主要任务。 |
| 符合现实世界 | 顶层目的地使用“练习、场景、我的”；离开练习使用“退出”，返回上一级使用“返回”，不得混用。 |
| 用户控制与自由 | 次级页始终提供返回；草稿或录音存在时退出需确认；确认框允许继续练习。 |
| 一致性与标准 | 所有普通次级页共用顶部栏；所有顶层页共用三项底栏；相同状态使用相同颜色、动词和布局。 |
| 错误预防 | 防止重复提交、误退未提交内容、危险数据误删，以及固定层遮挡当前输入。 |
| 识别优于记忆 | 当前等级和筛选必须可见；已选但滑出屏幕的筛选应自动回到可视区域；返回后恢复用户上下文。 |
| 灵活高效 | 语音和键盘入口并列但不同时争夺空间；筛选可深链；熟练用户可用系统返回和直接 URL。 |
| 美观与极简 | 一屏只保留一个主操作；更新提示、帮助和次要说明使用渐进披露，不占据主要视觉层级。 |
| 错误识别与恢复 | 错误文案说明发生了什么、数据是否保留以及下一步操作；可重试错误提供明确按钮。 |
| 帮助与文档 | 麦克风、安装、隐私和离线说明必须可随时找到；安装页始终展示手动步骤。 |

## 4. 信息架构与页面层级

### 4.1 一级目的地

一级目的地保持三项，不增加第四项：

- 练习：`/practice`
- 场景：`/scenes`
- 我的：`/me`

这三个页面使用 `AppShell` 和固定底部导航。底栏当前项使用图标填充、文字颜色和背景共同表达，并保留 `aria-current="page"`。

### 4.2 次级页面

普通次级页使用统一 `MobilePageHeader`：

- 场景准备：`/scenes/[slug]`
- 隐私与数据：`/privacy`
- 安装到手机：`/install`
- 同步登录：`/auth`
- 重新设置目标：`/welcome`，仅在已存在用户资料时显示返回入口

普通次级页不显示底部导航，避免在详情和设置流程中产生两个竞争性的导航层。顶部栏包含至少 44 × 44 px 返回按钮、短标题和可选的尾部操作。

### 4.3 沉浸式流程

对话练习和完成态属于沉浸式流程：

- 对话：`/session/[id]`
- 复盘：`/session/[id]/report`

对话页隐藏底栏，保留左上角“退出本次练习”。复盘页不恢复底栏，底部提供“回到今日练习”和“换个场景”两个显式出口，并在顶部提供“返回学习中心”或历史返回入口。

### 4.4 标准用户旅程

```text
/ → /welcome → /practice
                   ├─ /scenes → /scenes/[slug] → /session/[id]
                   │                              └─ 完成态 → /session/[id]/report
                   └─ /me ─┬─ /privacy
                            ├─ /install
                            ├─ /auth
                            └─ /welcome
```

## 5. 导航与返回契约

### 5.1 返回目标

| 当前页面 | 站内返回的默认目标 | 历史返回策略 |
| --- | --- | --- |
| `/scenes/[slug]` | `/scenes`，保留筛选参数 | 若上一条同源历史属于 SpeakMate，则优先 `router.back()`；否则使用默认目标。 |
| `/session/[id]` | 对应场景准备页及等级 | 若存在未提交草稿、录音或处理中请求，先进入退出确认；否则按同源历史优先规则返回。 |
| `/session/[id]/report` | `/me` | 同源历史有效时允许历史返回，但不得返回到已完成且不可继续提交的练习交互态。 |
| `/privacy` | `/me` | 同源历史优先，失败时回 `/me`。 |
| `/install` | `/me` | 同源历史优先，失败时回 `/me`。 |
| `/auth` | `/me` | 同源历史优先，失败时回 `/me`。 |
| 已有资料时的 `/welcome` | `/me` | 同源历史优先，失败时回 `/me`。 |

### 5.2 历史安全规则

1. 只把同源 SpeakMate 页面视为可安全返回历史。
2. 直接打开深层 URL 时，返回按钮必须使用表中的默认目标，不能把用户带到空白页或外站。
3. 顶层底栏使用正常的可回退导航，不使用 `location.replace()`。
4. 从场景库进入详情时，把当前筛选完整写进详情页的 `from` 或可重建查询参数；详情页返回时恢复该 URL。
5. 复盘后的主操作使用目标明确的链接，不依赖模糊的浏览器历史。
6. 页面切换期间只显示一次目标页面，不创建中间空白路由。

### 5.3 练习退出保护

出现以下任一条件时，站内退出和 `popstate` 返回均触发退出确认：

- 正在录音；
- 已录音但尚未确认；
- 文字输入非空且尚未提交；
- 轮次正在提交或接收回复。

确认面板包含：

- 标题：“退出本次练习？”
- 说明：明确已提交轮次会保留，当前未提交内容会丢失；处理中状态说明请等待或稍后恢复。
- 次操作：“继续练习”
- 破坏性操作：“退出”

没有未提交状态时不弹确认，避免过度打断。浏览器刷新和关闭页面仅在存在未提交内容时使用原生 `beforeunload` 防护。

## 6. 共享移动组件

### 6.1 `MobilePageHeader`

职责：为普通次级页面提供统一返回、标题、安全区和焦点锚点。

- 高度至少 56 px，加 `env(safe-area-inset-top)`。
- 返回触控区至少 44 × 44 px，图标使用现有 Phosphor `ArrowLeft`。
- 标题使用一个可聚焦的页面级 `h1` 或指向页面 `h1` 的语义关系。
- 背景、边框和文字颜色从现有令牌中选择，不增加新品牌色。
- 可选尾部操作不得挤压标题；空间不足时只保留图标和无障碍名称。

### 6.2 `SmartBackLink`

职责：封装同源历史优先、默认路由兜底和可选退出保护。

公开输入：

- `fallbackHref`
- `ariaLabel`
- `guardState`：`clean | draft | recording | processing`
- `onBeforeLeave`：可选

组件不读取业务数据库，只接收调用方提供的轻量导航状态，便于单元测试。

### 6.3 `RouteAnnouncerAndFocus`

职责：在客户端路由完成后管理焦点与播报。

- 顶层目的地切换后滚动到顶部，并把焦点移至页面主标题。
- 历史返回时保留浏览器恢复的纵向位置，不强制置顶。
- 动态标题变化通过礼貌的隐藏状态区域播报一次。
- 不在输入框已主动获得焦点时抢夺焦点。

### 6.4 `ScrollToTopButton`

职责：在长场景列表向下超过两个视口后提供快速返回顶部。

- 固定于底部导航上方并避开安全区。
- 至少 44 × 44 px，使用 `ArrowUp` 图标和“返回顶部”无障碍名称。
- 只在 `/scenes` 且滚动阈值达到后显示。
- 普通模式平滑滚动；减少动画模式立即滚动。

### 6.5 `UpdateSnackbar`

替代现有顶部更新卡片。

- 位置：普通页面位于底栏上方；次级页位于底部安全区上方。
- 不在 onboarding、录音、文字确认、提交、接收和完成转场期间出现。
- “稍后”选择使用等待 Worker 的版本标识保存在 `sessionStorage`；同一版本本次会话不重复显示。
- 主操作为“安全更新”，次操作为“稍后”。
- 更新失败时不刷新，显示“暂时无法更新，可稍后重试”。

## 7. 页面设计规格

### 7.1 首屏与新用户引导

1. 首屏继续使用现有单主 CTA，不显示底部导航。
2. 更新 Snackbar 不得出现在首次引导期间。
3. 引导顶部显示当前步骤和总步骤；返回使用顶部 44 px 图标按钮，底部文字返回可移除，避免重复导航。
4. 当前选项使用颜色、边框和勾选图标共同表达，并设置 `aria-pressed`。
5. 已有资料的用户从“重新设置目标”进入时显示关闭/返回；全新用户首步不显示无意义返回。
6. 完成后进入 `/practice`，并将焦点移至首页主标题。

### 7.2 今日练习

1. 保留推荐场景和“浏览全部场景”结构。
2. 等级徽章必须来自已保存资料，与场景库初始等级相同。
3. 存在活动会话时 CTA 为“继续本次对话”；不存在时为“准备开始”。
4. 更新 Snackbar 显示时不能覆盖标题、推荐卡或底栏。

### 7.3 场景库

筛选状态使用 URL 作为公开真相：

```text
/scenes?q=hotel&category=travel&level=B1&duration=8
```

规则：

1. 缺少 `level` 时异步读取用户资料；读取完成前显示稳定骨架，不能先渲染 A2 再跳到 B1。
2. URL 中有效参数优先于资料默认值。
3. 搜索输入使用 250 ms 防抖更新 URL；按钮筛选立即更新 URL。
4. 无效参数回落到安全默认值，但不抛出错误页。
5. 进入详情和返回时保留查询参数、纵向位置和当前筛选。
6. 分类和时长行允许横向原生滚动，使用 `overscroll-behavior-inline: contain`、触摸惯性和 scroll snap。
7. 可横向滚动时，尾部显示轻微渐隐；已到末端时相应渐隐消失。
8. 选中筛选后调用 `scrollIntoView({ block: 'nearest', inline: 'center' })`，确保当前项始终可见。
9. 每个筛选按钮至少 44 px 高，设置 `aria-pressed`。
10. 在筛选区下方显示可读摘要和“清除筛选”；无筛选时不显示多余清除按钮。
11. 无结果状态说明当前条件，并提供“清除筛选”恢复操作。
12. 场景卡的标题、图片和箭头共同成为一个完整链接，不能只有右下角箭头可点击。

### 7.4 场景准备

1. 顶部使用 `MobilePageHeader`，返回场景库并保留筛选上下文。
2. Hero、角色、任务、关键词和示例表达继续使用现有布局。
3. 底部主 CTA 保持 sticky，但页面底部增加等于 CTA 高度和安全区的内容留白。
4. CTA 获得焦点时必须完整可见。
5. 横屏时 Hero 高度受限，优先保留标题、目标和 CTA。

### 7.5 对话舞台

1. 保留现有 Atlantic 沉浸式顶部、场景图、英文大句和 Coral 语音操作。
2. 左上退出按钮触控区扩展至 44 × 44 px；图标位置不变。
3. 语音模式下显示固定 `SpeechDock`；内容区底部留白必须等于 Dock 实际高度、安全区和 16 px 缓冲。
4. 打开文字确认后，隐藏语音波形和录音主按钮，切换到 `TextReviewDock`。
5. `TextReviewDock` 包含 textarea、字符状态、取消和提交，并使用 `visualViewport` 或 `dvh` 适配 iPhone 虚拟键盘。
6. textarea 获得焦点后，其标签、至少两行内容和提交按钮必须同时处于可视区域。
7. 键盘关闭后恢复语音 Dock，不保留无意义的底部空白。
8. 展开单轮反馈后，把反馈标题和新增内容滚动至 Dock 上方完整可见位置。
9. 处理中禁用录音、键盘输入和重复提交，状态区域使用 `role="status"`。
10. 网络错误保留草稿，并提供“重新提交”和“返回编辑”；无声错误不消耗轮次。
11. 达成目标后，“完成场景并查看复盘”放在反馈之后、Dock 之上，并保持完整可见。

### 7.6 完成态与复盘

1. 完成态继续保留全屏庆祝视觉与唯一主 CTA。
2. 系统返回不得恢复成可继续提交的旧交互态；已完成会话只能进入只读复盘或场景页。
3. 复盘页顶部提供统一返回，底部显式提供“回到今日练习”和“换个场景”。
4. 收藏按钮至少 44 × 44 px；成功后图标、禁用状态和屏幕阅读器状态同步更新。
5. 复盘长页使用自然纵向滚动，不嵌套新的纵向滚动容器。

### 7.7 学习中心、隐私和同步

1. 学习中心继续使用底部导航。
2. 最近练习链接根据状态进入活动会话或只读复盘。
3. 隐私、安装、同步和重新设置目标都使用相同的次级页顶部栏。
4. 数据导出成功、失败和清空成功必须在控件附近给出可感知状态。
5. 清空数据继续要求输入“清空”，并在执行前给出最终确认；完成后返回全新用户状态。

### 7.8 安装到手机

1. 页面始终显示 `iPhone` 和 `Android` 两个可切换说明，不依赖平台识别决定是否渲染。
2. iPhone 默认步骤：Safari 打开 → 分享 → 添加到主屏幕 → 确认添加。
3. Android 默认步骤：浏览器菜单 → 安装应用或添加到主屏幕 → 确认安装。
4. 已捕获 `beforeinstallprompt` 时，Android 面板增加原生“安装应用”按钮。
5. 已处于 standalone 模式时显示“已安装到主屏幕”，隐藏重复安装 CTA。
6. 微信内置浏览器中显示“请使用系统浏览器打开”的说明，但不得形成死路；保留复制地址或继续练习入口。
7. 顶部返回学习中心，底部提供继续练习。

## 8. 滚动、固定层与安全区

### 8.1 纵向滚动

1. 每个页面只允许一个主纵向滚动容器，默认使用文档滚动。
2. `html` 设置与固定顶部、底部组件相匹配的 `scroll-padding`。
3. 路由前进默认到顶部；历史返回交给浏览器恢复，并通过筛选 URL 重建相同内容高度。
4. 固定底栏、Snackbar 和 Dock 必须共享 z-index 层级表，禁止互相覆盖。
5. 页面内容底部留白由实际固定组件高度和 `env(safe-area-inset-bottom)` 共同决定。

### 8.2 横向滚动

1. 仅分类筛选和时长筛选允许横向滚动。
2. 页面根节点不得出现横向溢出；所有验证视口的 `scrollWidth - clientWidth` 不得超过 1 px。
3. 横向容器保留触摸滑动，不使用拖拽库或自定义惯性。
4. 渐隐只表达“还有内容”，不承载交互；屏幕阅读器仍能访问全部筛选按钮。
5. 键盘用户可逐项 Tab，聚焦项自动滚入可视区。

### 8.3 层级表

| 层级 | 用途 |
| --- | --- |
| 10 | sticky 页面操作和筛选摘要 |
| 20 | 底部导航、语音 Dock、文字确认 Dock |
| 30 | 更新 Snackbar、轻量 Toast |
| 40 | 退出确认、危险操作确认 |

同一层级在同一时刻只能有一个主要固定组件。打开确认面板时，背景不可交互并锁定文档滚动。

## 9. 响应式与手机规范

### 9.1 目标尺寸

- 最小：320 × 568，仅保证关键任务可完成。
- 主要手机：360 × 800、390 × 844、430 × 932。
- iPhone 横屏：844 × 390。
- 平板：768 × 1024。
- 桌面：内容保持最大 480 px 居中，不拉伸成桌面仪表盘。

### 9.2 触控与排版

1. 所有按钮、链接、筛选和图标操作的可点击区域至少 44 × 44 px。
2. 相邻触控目标至少保留 8 px 间距，分段控件内部通过边界和足够宽度避免误触。
3. 正文默认不小于 14 px，重要说明不依赖低对比度小字。
4. 支持浏览器 200% 字号；不得隐藏主操作或产生页面根横向滚动。
5. 不禁用用户缩放。
6. 所有固定区域使用 `viewport-fit=cover` 与安全区变量。

### 9.3 动效

1. 交互过渡保持 160–240 ms。
2. 只对 `transform` 和 `opacity` 做动画。
3. `prefers-reduced-motion: reduce` 时关闭自动平滑滚动、脉冲和非必要转场。
4. 不增加大面积背景动画或自定义页面滑动转场。

## 10. 无障碍要求

1. 每页只有一个主要 `h1`，标题层级连续。
2. 路由变化后页面标题和焦点位置可被屏幕阅读器感知。
3. 底部导航使用 `nav` 和可读标签；当前项使用 `aria-current`。
4. 筛选使用 `aria-pressed`，横向容器使用可读分组名称。
5. 展开反馈使用 `aria-expanded` 和稳定的内容关系。
6. 图标按钮必须有明确中文无障碍名称。
7. 焦点指示至少保持当前高对比 3 px 轮廓；固定组件不得完全遮挡焦点。
8. 状态更新使用礼貌播报；错误使用 `role="alert"`，不得同时重复播报相同内容。
9. 颜色不是状态的唯一表达方式，选中、成功、警告和错误同时使用图标或文字。
10. 语音不是完成练习的唯一方式，键盘输入入口始终可用。

## 11. 错误与边界状态

| 状态 | 用户看到的内容 | 恢复操作 |
| --- | --- | --- |
| 本地资料读取失败 | 说明记录未被清除 | 重新读取、刷新 |
| 麦克风拒绝 | 说明权限用途和系统设置路径 | 打开文字输入、重试权限 |
| 无声或过短 | 不扣轮次，说明未识别到有效声音 | 重新录音、文字输入 |
| 上传或 AI 超时 | 保留录音/文字草稿和当前轮次 | 重新提交、返回编辑 |
| 离线 | 标明可浏览内容与不可用能力 | 网络恢复后重试 |
| 会话不存在 | 说明记录可能已清除 | 回到今日练习、换个场景 |
| 更新失败 | 当前版本继续可用 | 稍后重试 |
| 安装能力不可用 | 始终展示手动安装步骤 | 继续练习 |

## 12. 状态与数据流

### 12.1 场景筛选

```text
用户资料等级 ─┐
             ├─ 解析有效初始状态 → URL 查询参数 → SceneLibrary 过滤结果
直接 URL 参数 ─┘                          │
                                         ├─ 详情链接携带来源状态
用户修改筛选 ────── 防抖/立即更新 URL ────┘
```

URL 是可分享、可恢复的公开状态；用户资料只是缺少 URL 等级时的默认来源。组件不得维护一份与 URL 无法对齐的长期副本。

### 12.2 练习交互模式

```text
ready/voice → recording → reviewing/audio-or-text → submitting → receiving → ready
                    └─ cancel ───────────────────────────────────────→ ready
                    └─ recoverable-error → edit/retry ──────────────→ submitting
ready + goals complete → completed → report
```

底部操作区由状态机状态派生：

- `ready`、`recording`：`SpeechDock`
- `reviewing`、带草稿的 `recoverable-error`：`TextReviewDock`
- `submitting`、`receiving`：处理状态 Dock，禁用重复操作
- `completed`：无 Dock，显示完成态

## 13. 测试策略

实施必须遵循测试驱动：先添加失败测试，再实现最小改动，通过后重构。

### 13.1 单元与组件测试

1. `SmartBackLink`：同源历史、直接深链、默认兜底、守卫状态。
2. 场景查询参数：有效值、无效值、资料默认值、序列化与反序列化。
3. 场景库：B1 资料默认、筛选摘要、清除、无结果恢复、`aria-pressed`。
4. `UpdateSnackbar`：安全页面显示、沉浸状态抑制、同版本“稍后”记忆、更新失败。
5. 对话页：文字模式隐藏语音 Dock、草稿退出确认、处理中禁用、反馈展开滚入可视区。
6. 安装页：iPhone、Android、standalone、微信内置浏览器和未知平台。
7. 路由焦点：前进聚焦标题、历史返回不抢输入焦点。

### 13.2 端到端测试

在 Chromium mobile 和 WebKit iPhone 两个项目执行：

1. 首次进入 → 引导三步 → 今日练习。
2. 今日练习 → 场景库 → 设置 B1/社交/5 分钟 → 进入详情 → 返回，筛选与位置不变。
3. 直接打开场景详情 → 返回，安全落到场景库。
4. 场景详情 → 对话 → 打开键盘 → 输入 → 提交 → 展开反馈 → 完成 → 复盘。
5. 存在文字草稿时点击退出和系统返回，确认面板均能保留或放弃。
6. 无草稿退出不显示多余确认。
7. 更新提示不出现在引导、录音和文字确认状态，也不遮挡底栏。
8. 安装页在未知平台仍显示两套步骤。
9. 场景长列表可纵向滚动、返回顶部；分类和时长可横向滚动并保持选中项可见。
10. 离线恢复、重复提交、错误重试和完成会话不可重复写入。

### 13.3 布局与无障碍测试

对 320 × 568、360 × 800、390 × 844、430 × 932、844 × 390 和 768 × 1024 验证：

- 页面根横向溢出不超过 1 px。
- 主操作、返回、底栏和当前焦点完整可见。
- 固定层不相互覆盖。
- iPhone 底部安全区不吞掉 CTA。
- 200% 字号仍可完成核心流程。
- 键盘 Tab 顺序、可见焦点、可访问名称和 Axe 自动规则无新增严重问题。

### 13.4 视觉 QA

1. 以现有 `docs/design/speakmate-dialogue-stage-reference.png` 为视觉基线。
2. 在相同 390 × 844 视口对比关键页面，不改变品牌色、字体层级、图片裁切和主 CTA 形态。
3. 检查圆角、间距、边框、阴影、文本截断、安全区和固定组件位置。
4. 视觉截图不能代替交互与无障碍测试；两类证据必须同时通过。

## 14. 验收标准

以下条件必须全部满足：

1. 所有现有路由均有明确入口、退出和深链返回兜底，不产生跳错页面或死路。
2. 已保存 B1 用户打开场景库时初始等级为 B1；有效 URL 参数可覆盖默认等级。
3. 场景筛选进入详情后返回保持搜索、分类、等级、时长和纵向位置。
4. 横向筛选可被触摸、键盘和屏幕阅读器使用，当前选项保持可见。
5. 文字输入、提交按钮和展开反馈不会被语音 Dock、底栏、Snackbar 或虚拟键盘遮挡。
6. 所有交互目标至少 44 × 44 px，固定层尊重 iPhone 安全区。
7. 安装页在未知平台仍有完整 iPhone 与 Android 手动说明。
8. 更新提示不遮挡内容，同版本“稍后”在会话内不重复出现。
9. Chromium 和 WebKit 的现有测试及新增测试全部通过；能力相关跳过必须有明确原因。
10. `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build` 和完整 Playwright 回归通过。
11. 关键手机视口设计 QA 无已知高优先级视觉差异。
12. 部署后对公开 Vercel URL 完成健康检查、主流程冒烟和 iPhone WebKit 回归。

## 15. 预计代码边界

实施阶段预计涉及以下边界，最终文件拆分由实施计划确定：

- `src/components/app-shell/`：移动顶部栏、智能返回、路由焦点、返回顶部和固定层协议。
- `src/components/install-prompt/`：更新 Snackbar 与安装平台说明。
- `src/features/scenes/`：查询参数状态、筛选滚动、整卡链接和详情顶部栏。
- `src/features/practice/`：退出守卫、文字确认 Dock、反馈滚动和完成态返回。
- `src/features/onboarding/`：统一步骤返回与已有资料模式。
- `src/app/`：页面组合、全局滚动和安全区变量。
- `tests/e2e/`：导航、返回、滚动、虚拟键盘近似、安装与跨浏览器回归。

这些改动不得影响 AI 提供商契约、IndexedDB 数据模式和既有场景内容版本。

## 16. 发布与回滚

1. 先在本地生产构建中完成单元、E2E 和设计 QA。
